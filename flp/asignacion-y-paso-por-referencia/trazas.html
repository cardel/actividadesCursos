Trazas con asignación

Cinco programas para trazar completos: un acumulador que la recursión actualiza desde afuera, un parámetro que se asigna en dos llamadas sin que la variable de afuera se entere, tres llamadas que escriben en la misma celda, un procedimiento recursivo al que se le intenta asignar otro, y un programa que no crea ningún ambiente y aun así cambia dos celdas. Se predicen el valor y los conteos; al comprobar, la página abre la traza con cada reserva y cada asignación marcadas, y la cadena de ambientes con el almacén debajo.

El lenguaje es el del interpretador con asignación: números, variables, true y false, las primitivas antes del paréntesis y con comas (+(e,e), -(e,e), *(e,e), add1(e), sub1(e), >(e,e), ==(e,e)), if e then e else e, let id = e … in e, proc(id, …) cuerpo, letrec, la aplicación (rator rand …), que va sin comas, begin e; e; … end y set id = e, que devuelve 1. El ambiente inicial liga x = 4, y = 2, z = 5 sobre a = 4, b = 5, c = 6. La página hace lo mismo que el interpretador en Racket, con sus verificaciones: boolean? en la prueba del if, procval? en el operador y la cantidad de argumentos. Cada programa empieza con el ambiente inicial recién creado.

El ambiente inicial en DrRacket

Cada programa empieza de cero, aquí y en DrRacket: evaluar-programa llama a initialize-store! y construye un ambiente inicial nuevo, con seis celdas nuevas para x, y, z, a, b y c. Después de begin set x = 99; x end, el programa x vuelve a dar 4. Desde el REPL, (almacen->lista) muestra el almacén que dejó el último programa.

El 99 quedó en la celda 0 del almacén del primer programa, y ese almacén ya no existe cuando corre el segundo.
