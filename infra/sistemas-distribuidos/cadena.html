Disponibilidad de una cadena de servicios

Una solicitud web pasa por varias piezas antes de volver, y cada una tiene sus nueves. Aquí se calcula qué queda de esos nueves cuando las piezas van una detrás de otra, qué compra una copia y qué hacer con un nodo que no contesta.

1. Tres piezas en serie

Cada solicitud cruza un balanceador, un servidor de aplicación y una base de datos. Si cualquiera de los tres está caído, la solicitud falla. Las tres fallan de forma independiente.

2. Una copia de la base de datos

Se agrega una segunda base de datos con el mismo 99,9 %, y el servicio usa la que esté viva. La pieza solo cae si caen las dos copias a la vez.

¿Cuántas horas al año queda caído ahora el servicio?
La cuenta supone que las copias fallan por separado. Dos bases en el mismo rack, con la misma fuente de poder, caen juntas, y entonces la copia no compra nada: por eso las réplicas se reparten entre zonas.
