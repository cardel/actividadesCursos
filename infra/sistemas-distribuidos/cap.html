El teorema CAP, paso a paso

Mientras la red funciona, un sistema distribuido parece tenerlo todo. La elección aparece cuando la red se parte, y entonces hay que decidir si se contesta con un dato viejo o no se contesta. Aquí se recorre esa partición momento por momento.

1. Las tres propiedades

La consistencia se define como toda lectura devuelve la escritura más reciente o un error. ¿Qué permite esa última cláusula?

2. La partición, momento por momento

Dos nodos, A y B, con el mismo dato x = 3. La red entre ellos se cae. Un cliente escribe x = 5 en A; otro cliente lee x en B.

MomentoABResponde CPResponde AP

Con la red partida y x = 5 ya escrito en A, un cliente lee en B. ¿Qué contesta un sistema CP?

¿Y un sistema AP?

Cuando la red vuelve, los dos sistemas terminan en x = 5. La diferencia es qué pasó durante la partición, y es irreversible: el cliente de AP ya se fue con un 3 en la mano. El mismo dilema en un cajero: la opción CP dice fuera de servicio; la AP deja retirar hasta cierto monto y reconcilia después, aceptando que alguien se sobregire.

3. Seis sistemas, una decisión cada uno

Para cada uno, qué conviene sacrificar durante una partición. La regla general: si el costo de un dato incorrecto supera el costo de un error visible, CP; si es al revés, AP.

4. ACID y BASE

Dos conjuntos de garantías que acompañan las dos decisiones.

SiglaQué prometeDónde aparece

Sin escrituras nuevas, todos los nodos convergen al mismo valor. ¿Qué garantiza esa frase?

PostgreSQL y MySQL en un solo nodo son CA, y dejan de serlo al replicar entre regiones: ahí hay que elegir. Un sistema CA solo existe si la red no falla, que en distribuido no pasa.
