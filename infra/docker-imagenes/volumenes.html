Lo que sobrevive al contenedor

La capa escribible nace con el contenedor y muere con él. Siga la secuencia que lo demuestra con un archivo de texto, repítala con una base de datos de verdad y decida qué pasa cuando dos contenedores montan el mismo volumen.

1. Un archivo que no estaba

$docker run --name efimero alpine sh -c 'echo dato > /archivo.txt; cat /archivo.txt'
$docker rm efimero
$docker run --rm alpine cat /archivo.txt
PasoResultadoDónde vivía el dato
El tercer contenedor es otro: arranca de las mismas capas de la imagen, en modo lectura, y con una capa escribible vacía. El archivo no desapareció del disco al leerlo, desapareció al borrar el contenedor que lo tenía.

2. La misma secuencia con una base de datos

$docker volume create pgdata
$docker run -d --name pg -e POSTGRES_PASSWORD=clave -v pgdata:/var/lib/postgresql/data postgres:16-alpine
$docker exec -it pg psql -U postgres -c "CREATE TABLE nota(t text); INSERT INTO nota VALUES ('persiste');"
$docker rm -f pg # y se vuelve a levantar igual
$docker exec -it pg psql -U postgres -c "SELECT * FROM nota;"

¿Qué devuelve ese último SELECT?

3. Un volumen, dos contenedores

$docker run -d --name escritor -v datos:/var/datos alpine \
sh -c 'while true; do date >> /var/datos/log.txt; sleep 5; done'
$docker run --rm -v datos:/var/datos alpine tail -n 3 /var/datos/log.txt

El segundo contenedor no escribió nada y se borra al salir. ¿Qué imprime su tail?

Y docker volume prune, ¿qué borra?

Un volumen que nadie monta no avisa de que está ahí, y ocupa lo que ocupaba: docker volume ls los lista y docker volume inspect dice en qué ruta del anfitrión quedó cada uno.
