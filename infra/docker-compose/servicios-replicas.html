Tres réplicas, tres nodos, un puerto

Una orden crea el servicio y el clúster hace el resto: cuenta las réplicas, las reparte entre los nodos y publica un puerto que no pertenece a ninguno. Lo último es lo que Compose plano no puede imitar.

1. La columna REPLICAS

$docker service create --name web --replicas 3 --publish 8080:80 nginx:alpine
verify: Waiting 1 seconds to verify that tasks are stable...
verify: Service 6cai30zq7r89l6w9hcts1xppr converged
$docker service ls
ID NAME MODE REPLICAS IMAGE PORTS
6cai30zq7r89 web replicated 3/3 nginx:alpine *:8080->80/tcp

¿Qué cuentan los dos números de 3/3?

Mientras una de las tareas todavía arranca, ¿qué se lee en esa columna?

2. El servicio y la tarea

docker service ls habla del servicio; docker service ps baja al nivel de la tarea. Diga dónde se lee cada dato.

La frontera es útil cuando algo va mal: el servicio dice cuántas faltan y la tarea dice en qué nodo se quedó la que falta.

3. El reparto entre los nodos

$docker service ps web --format 'table {{.Name}}\t{{.Node}}\t{{.CurrentState}}'
NAME NODE CURRENT STATE
web.1 nodo3 Running 15 seconds ago
web.2 cardel-desktop Running 13 seconds ago
web.3 nodo2 Running 15 seconds ago

La orden no dijo en qué nodo poner cada réplica. ¿Quién decidió ese reparto?

web.2 quedó en cardel-desktop, que es el manager. ¿Es un problema?

4. Un puerto del servicio, no de la réplica

La columna PORTS dice *:8080->80/tcp. Se pide http://nodo2:8080/ y en ese nodo la réplica es web.3. ¿Qué contesta?

El mismo servicio en Compose plano: docker compose up -d --scale web=3 con ports: 8080:80. ¿Qué pasa?

Si el servicio se queda en Compose plano y hay que repartir tráfico real entre varias réplicas, ¿qué hace falta?

De ahí que el puerto sea la diferencia que más se nota al pasar a Swarm: el servicio publica una vez y el clúster entero contesta, sin que nadie monte un balanceador a mano ni invente un puerto por réplica.

5. Para resolver en la máquina

Cree un servicio de nginx:alpine con dos réplicas y súbalo a tres con docker service scale. Siga con docker service ps en qué estado va cada tarea mientras converge, y después baje a una y diga cuál se quedó y por qué el puerto publicado responde igual durante todo el cambio.
