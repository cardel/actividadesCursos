Anatomía del compose.yml

El archivo tiene cuatro secciones de raíz y, dentro de cada servicio, claves que se parecen a dos de ellas sin ser lo mismo. Ahí está el error que más se comete. Diga qué va en cada sección, qué línea es una referencia y cuántos contenedores salen de tres servicios.

1. Las cuatro secciones de raíz

Para cada cosa que hay que declarar, elija la sección donde va. Una de las filas no corresponde a ninguna de las cuatro.

3. Un servicio es una imagen con N réplicas

El archivo de arriba, con cache agregado, declara tres servicios y ninguna línea de réplicas. ¿Cuántos contenedores aparecen en docker compose ps tras docker compose up -d?

$docker compose ps
NAME IMAGE SERVICE STATUS
proyecto-cache-1 redis:7-alpine cache Up 14 seconds
proyecto-db-1 postgres:16 db Up 14 seconds
proyecto-web-1 proyecto-web web Up 14 seconds

Los tres nombres terminan en 1. ¿Qué dice ese número?

En el archivo de los healthchecks, db y migrate declaran los dos image: postgres:16, y migrate además un command con el psql de la migración. ¿Son el mismo servicio?

4. Para resolver en la máquina

Escriba desde cero un compose.yml con un servicio de nginx:alpine que publique el 8080, monte un volumen nombrado en /usr/share/nginx/html y entre a una red propia, con las secciones de raíz que eso pida. Levántelo, compruebe con docker volume ls y docker network ls qué nombres les puso Compose, y diga de dónde sale la primera parte de cada nombre.
